# Приём готовых кропов в RD WEB

Портал ИД присылает в RD WEB **готовые растры блоков** с метаданными. RD WEB сохраняет их,
распознаёт своим конвейером и складывает результат в БД. Портал забирает результат прямым `SELECT`
из вью под read-only ролью.

PDF в RD WEB не передаётся. Документа у внешнего блока нет — есть картинка, её хэш и координаты на
странице. Геометрия, разворот и DPI уже применены к пикселям: перерезать и доворачивать растр не
нужно.

Дальше: что уходит в запросе (раздел 1), что обязано сохраниться и с какими ограничениями
(разделы 2–3), что портал читает обратно (разделы 4–5).

---

## 1. Ручка приёма

```
POST /api/v1/external-crops/batch
Content-Type: multipart/form-data
Authorization: Bearer <токен служебного принципала>
```

Один запрос = одна страница исходного комплекта = **1..16 кропов**.

Части запроса:

| Часть         | Content-Type                 | Содержимое                                 |
| ------------- | ---------------------------- | ------------------------------------------ |
| `manifest`    | `application/json`           | Манифест батча (ниже)                      |
| `<part_name>` | `image/png` или `image/jpeg` | Байты одного кропа. По одной части на кроп |

Имя части с байтами задаётся полем `part_name` соответствующей записи `crops[]`.

### 1.1. Манифест батча

| Поле                | Тип          | Обяз. | Значение                                               |
| ------------------- | ------------ | ----- | ------------------------------------------------------ |
| `manifest_version`  | string       | да    | `"portal.crops.v1"`. Незнакомое значение → 422         |
| `project_id`        | string       | да    | Проект RD WEB, выделенный порталу                      |
| `external_batch_id` | string ≤ 64  | да    | Идентификатор прогона распознавания на стороне портала |
| `selections`        | object       | да    | Выбор исполнения по типам блоков (ниже)                |
| `crops`             | array, 1..16 | да    | Записи кропов (ниже)                                   |

`selections` — объект `{ "<block_type>": { … } }` для каждого типа блока, встречающегося в `crops[]`:

| Поле                | Тип    | Обяз. | Значение                              |
| ------------------- | ------ | ----- | ------------------------------------- |
| `provider_type`     | string | да    | Провайдер RD WEB                      |
| `model_id`          | string | да    | Модель                                |
| `prompt_profile_id` | string | нет   | Профиль промпта; `null` → дефолт типа |

### 1.2. Запись `crops[]`

| Поле                      | Тип                           | Обяз. | Значение                                                      |
| ------------------------- | ----------------------------- | ----- | ------------------------------------------------------------- |
| `external_id`             | string ≤ 128                  | да    | Идентификатор кропа. Глобально уникален, вычисляется порталом |
| `idempotency_key`         | string, 64 hex                | да    | `sha256(external_id + ":" + crop_sha256)`                     |
| `part_name`               | string                        | да    | Имя multipart-части с байтами этого кропа                     |
| `block_type`              | `text` \| `stamp`             | да    | Словарь RD WEB (`domain/enums.py:136-141`)                    |
| `content_type`            | `image/png` \| `image/jpeg`   | да    | MIME байтов части                                             |
| `crop_sha256`             | string, 64 hex                | да    | sha256 **байтов части**, нижний регистр                       |
| `crop_bytes`              | int > 0                       | да    | Длина байтов части                                            |
| `crop_width_px`           | int > 0                       | да    | Ширина растра                                                 |
| `crop_height_px`          | int > 0                       | да    | Высота растра                                                 |
| `page_index`              | int ≥ 0                       | да    | Номер страницы комплекта, 0-based                             |
| `sort_order`              | int ≥ 0                       | да    | Порядок блока внутри страницы                                 |
| `coords_norm`             | `[x0,y0,x1,y1]` float         | да    | bbox блока на странице, 0..1                                  |
| `content_rotation`        | `0` \| `90` \| `180` \| `270` | да    | Уже применён к пикселям. Ноль пишется явно                    |
| `crop_policy_version`     | string                        | да    | Версия геометрической политики портала                        |
| `encoding_policy_version` | string                        | да    | Версия политики кодирования портала                           |
| `render_dpi`              | int > 0                       | да    | DPI растеризации страницы (обычно 300)                        |
| `page_width_px`           | int > 0                       | да    | Ширина страницы при этом DPI                                  |
| `page_height_px`          | int > 0                       | да    | Высота страницы при этом DPI                                  |
| `rasterizer`              | string                        | да    | Подпись растеризатора портала (вид и версия)                  |

Имён файлов, ФИО, адресов, идентификаторов ревизий портала, текстов промптов и токенов в манифесте
нет и быть не должно.

### 1.3. Ответ

**HTTP 200** — запрос разобран. Исход каждого кропа в теле; `accepted` и `rejected` могут быть
непусты одновременно.

```json
{
  "accepted": [
    {
      "external_id": "…",
      "remote_block_id": "…",
      "remote_task_id": "…",
      "deduplicated": false
    }
  ],
  "rejected": [{ "external_id": "…", "code": "…", "message": "…" }]
}
```

| Код     | Когда                                                                            |
| ------- | -------------------------------------------------------------------------------- |
| 200     | Запрос разобран; исход каждого кропа — в теле                                    |
| 401/403 | Удостоверение неверно, отозвано или не даёт прав на `project_id`                 |
| 409     | `external_id` уже принят с ДРУГИМ `idempotency_key` (код `external_id_conflict`) |
| 413     | Тело больше потолка                                                              |
| 415     | `content_type` вне allowlist                                                     |
| 422     | Манифест не разобран, незнакомая `manifest_version`, битые или неполные поля     |
| 429/5xx | Перегрузка, недоступность                                                        |

Портал реагирует на эти коды по-разному (401/403 останавливают прогон, 413/415/422 валят страницу,
429/5xx повторяются), поэтому смешивать их нельзя.

### 1.4. Лимиты

- До 16 кропов в батче.
- До 8 МиБ на кроп; портал просит потолок тела запроса не ниже 32 МиБ.
- `content_type` из allowlist: `image/png`, `image/jpeg`.
- Желательна ручка `GET /api/v1/external-crops/limits`, отдающая действующие значения (прецедент —
  `upload_limits`, `api/routes/documents_upload.py:46`).

Проверки на границе выполняются **до декодирования**: MIME из allowlist, размер байтов, габариты из
заголовка. Существующий разбор заголовка (`central/guards.py`, `png_dimensions`) умеет только PNG —
для JPEG нужен свой.

## 2. Требования к приёму

| №   | Требование                                                                                                                                                                 | Приоритет |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| 1   | **200 = закоммиченная строка.** Ответ отдаётся после фиксации транзакции. Сразу после 200 строка видна во вью со `status='queued'`                                         | **P0**    |
| 2   | **`UNIQUE (external_id)` ограничением БД**, не проверкой в коде                                                                                                            | **P0**    |
| 3   | **Идемпотентность по `idempotency_key`**: тот же `external_id` + тот же ключ → 200, `deduplicated: true`, **те же** `remote_block_id` и `remote_task_id`, новой задачи нет | **P0**    |
| 4   | **Конфликт ключа**: тот же `external_id` + другой `idempotency_key` → 409 `external_id_conflict`. Тело минимальное                                                         | **P0**    |
| 5   | **Дедупликация по хэшу картинки запрещена.** Два разных `external_id` с идентичными байтами — законная ситуация, распознаются оба, строк во вью две                        | **P0**    |
| 6   | **Терминальная строка неизменна**: достигнув терминального статуса, не меняет ни `status`, ни текст, ни `result_id`. Новый результат по блоку — новый `result_id`          | **P0**    |
| 7   | **Ретеншн ≥ 30 суток** после терминального статуса                                                                                                                         | P1        |
| 8   | **Неизвестные ключи манифеста игнорируются**, а не отвергаются. Ломающее изменение — параллельной версией (`portal.crops.v2`, `portal_block_results_v2`)                   | P1        |

## 3. Хранение

Обязаны сохраниться и быть доступны во вью:

`external_id`, `external_batch_id`, `crop_sha256`, `block_type`, `page_index`, `sort_order`,
`content_type`, а также присвоенные RD WEB `remote_block_id`, `remote_task_id`, `result_id`.

Остальные поля манифеста (`coords_norm`, `content_rotation`, `crop_policy_version`,
`encoding_policy_version`, `render_dpi`, `page_width_px/height_px`, `rasterizer`, `crop_width_px`,
`crop_height_px`, `crop_bytes`) достаточно сохранить как есть — например, одним `jsonb`: портал их
обратно не читает, они нужны для диагностики на вашей стороне.

**`crop_sha256` во вью — эхо присланного значения**, а не пересчёт. Внутренний `model_input_digest`
считается по другой схеме (`contracts/crop_preprocess/v1/pixels.py:150-170`: домен-разделитель
`rd.modelin.1`, длина перед данными, префикс `sha256:`) и с плоским sha256 не совпадает по
построению. Портал сверяет эхо с отпечатком отправленных байтов при каждом чтении и при расхождении
текст не публикует.

### 3.1. Что нужно от конвейера

Сегодня подготовка вызова безусловно грузит документ и режет кроп сама
(`pipeline/processor_prepare.py:66-68`, `:155`), а `document_id` объявлен `NOT NULL` у блоков, задач
и job-ов (`030_blocks_results.sql:9`, `040_jobs_tasks.sql:9,41`). У внешнего блока документа нет,
поэтому нужна отдельная ветка исполнения:

| Точка                                                      | Что меняется                                                                                                                                      |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pipeline/processor_prepare.py:66-68`                      | Контейнер-документ на `external_batch_id` (идемпотентный, `file_name = external_batch_id`) либо снятие `NOT NULL`                                 |
| `pipeline/processor_prepare.py:155` (`build_crop`)         | Пропускается: байты берутся из загрузки по сохранённому ключу объекта                                                                             |
| `pipeline/lineage_record.py:93,98`                         | Ожидаемый хэш строится из загруженных байтов; `queue.crop_lineage` не отвергает сдачу за «чужой» растр (`api/services/agent_result.py:92-101`)    |
| `pipeline/processor_preflight.py:129`                      | Бюджет считается по присланным `crop_width_px`/`crop_height_px`                                                                                   |
| `pipeline/processor_preflight.py:401` (`rasterize_at_dpi`) | Ужатие при переполнении контекста — перекодированием растра, а не перерастеризацией `crop.pdf` (его нет)                                          |
| `pipeline/refinement/*`, `verification/*`                  | Определены для блока без документа (деградация или явное выключение). Зонд текстового слоя уже умеет `crop_pdf_missing` (`pdf_text_layer.py:167`) |
| `api/services/project_purge_tables.py:18,55`               | Новая таблица приёма внесена в `PURGED_TABLES` или `KEPT_TABLES` с причиной, иначе гард-тест каскада упадёт                                       |

Признак внешнего блока — новая колонка `blocks`. Имя на ваше усмотрение, но **не** `crop_source`: оно
уже занято другой осью — чем кормится модель на агентском узле, значения `''`, `local_shadow`,
`local` (`api/routes/_agent_schemas.py:199-201`).

**Не меняется:** схемы результатов (`StampBlockResult`, `domain/results.py:148-178` — поле-в-поле как
есть; номер листа портал добывает отдельным `text`-кропом и в схему штампа не просит), промпты,
модели, существующий путь «документ → детекция → job», векторный `crop.pdf` для внутренних блоков,
агентский путь.

## 4. Вью для чтения

Единственная поверхность чтения. Таблицы RD WEB портал не читает.

```sql
CREATE VIEW portal_block_results_v1 AS SELECT
  contract_version, external_id, external_batch_id,
  remote_block_id, remote_task_id, result_id,
  block_type, crop_sha256, status, result_type,
  ocr_markdown, ocr_text, ocr_json,
  model_id, prompt_profile_id, confidence, attempts, latency_ms,
  error_code, error_message, created_at, updated_at
FROM …;

CREATE INDEX … ON … (external_batch_id, external_id);
```

| Колонка             | Тип         | Значение                                                                                       |
| ------------------- | ----------- | ---------------------------------------------------------------------------------------------- |
| `contract_version`  | text        | Версия контракта вью                                                                           |
| `external_id`       | text        | Ровно то, что прислал портал. **Одна строка на `external_id`**                                 |
| `external_batch_id` | text        | Из манифеста                                                                                   |
| `remote_block_id`   | text        | Идентификатор блока в RD WEB                                                                   |
| `remote_task_id`    | text        | Идентификатор задачи в RD WEB                                                                  |
| `result_id`         | text        | Идентификатор результата; меняется только вместе с новым результатом                           |
| `block_type`        | text        | `text` \| `stamp`                                                                              |
| `crop_sha256`       | text        | Эхо присланного значения                                                                       |
| `status`            | text        | `queued` \| `running` \| `success` \| `suspicious` \| `error` \| `non_retriable` \| `canceled` |
| `result_type`       | text        | `html` \| `image_json` \| `stamp_json` \| `error` (`domain/enums.py:175-179`)                  |
| `ocr_markdown`      | text        | Текст блока; портал читает его первым                                                          |
| `ocr_text`          | text        | Запасной источник текста                                                                       |
| `ocr_json`          | jsonb       | Структурированный результат (для `stamp` — `StampBlockResult`)                                 |
| `model_id`          | text        | Модель, посчитавшая результат                                                                  |
| `prompt_profile_id` | text        | Профиль промпта                                                                                |
| `confidence`        | float       | 0..1                                                                                           |
| `attempts`          | int         | Число попыток                                                                                  |
| `latency_ms`        | int         | Длительность вызова                                                                            |
| `error_code`        | text        | Код отказа, если есть                                                                          |
| `error_message`     | text        | Текст отказа, если есть                                                                        |
| `created_at`        | timestamptz | Создание строки                                                                                |
| `updated_at`        | timestamptz | Последнее изменение                                                                            |

Портал делает два запроса на опрос: список `external_id` батча и строки по массиву ещё открытых
`external_id`. Оба должны быть индексными.

**Нужна таксономия статусов** (P1): для каждого значения `status` — окончателен ли он, может ли
строка после него измениться, есть ли смысл переотправлять кроп новым `external_id`. Для задач такой
словарь у вас уже есть (`domain/task_terminal.py:44-51`), для результата блока — нет.

**Желательна колонка `raw_output_sha256`** (P1) — хэш сырого текста ответа модели до разбора. Сам
текст хранить не нужно. Без неё портал считает хэш по колонкам вью, то есть видит изменения разбора,
а не изменения ответа модели.

## 5. Роль для чтения

`portal_reader`:

- `GRANT SELECT` **строго на вью** `portal_block_results_v1`; прав на таблицы нет;
- `CONNECTION LIMIT` (порталу достаточно 2);
- `statement_timeout` и `idle_in_transaction_session_timeout` на роли;
- TLS обязателен, CA-сертификат передаётся отдельно от пароля (портал подключается с
  `sslmode=verify-full`);
- сетевой allowlist по адресам портала, процедура ротации пароля.

Портал со своей стороны: `SELECT` только на вью, каждый опрос внутри `BEGIN TRANSACTION READ ONLY` с
`SET LOCAL statement_timeout`, пул на 2 соединения. В БД RD WEB портал не пишет ни при каком исходе.

**Удостоверение для приёма** (P1): токен службы с областью «только приём внешних кропов в указанные
проекты», хранимый хэшем, отличимый от JWT по префиксу — по образцу агентского механизма
(`domain/models_agents.py:43`, `api/services/agent_auth.py:14-16`). До него — отдельный служебный
аккаунт, не тот, которым ходит легаси-интеграция портала.

## 6. Вопросы

1. **Потолок тела запроса на ingress** на боевом контуре. Конфигурации обратного прокси в
   репозитории нет, потолок известен только эксплуатации. Если он ниже 8 МиБ — понадобится
   presigned-загрузка растра по образцу `upload/init` вместо multipart.
2. **`crop_model_dpi`** (`core/settings_models_queue_provider.py:18`, значение 300) описывает
   растеризацию вашего кропа. Подтвердите, что на внешней ветке она не применяется.
3. **Меняют ли `refine`/`verify` `result_id` уже терминальной строки?** У результата есть
   `result_phase`, `source_result_id`, `is_final` (`030_blocks_results.sql:41-43`) — портал должен
   знать, увидит ли он смену `result_id` после потребления и при каких настройках job-а.
4. **Разбор заголовка JPEG** на входящей границе — добавляете или порталу ограничиться PNG? PNG
   стоит трафика: 220 полностраничных кропов дают 1–2.5 ГБ против 150–250 МБ в JPEG q=85.
5. **Автоматическая уборка результатов по сроку** — есть ли она на уровне эксплуатации и
   распространяется ли на строки внешнего батча (требование 7 раздела 2)?

## 7. Проверка

Пробник портала (`pnpm rdcrop:probe`) выполняет один сквозной цикл:

1. `POST` двух кропов (`text` и `stamp`) → 200, два `accepted`;
2. немедленный `SELECT` из вью под `portal_reader`, без задержки → две строки, `status='queued'`;
3. опрос до терминального статуса → `success` на обеих;
4. `crop_sha256` во вью посимвольно равен отправленному;
5. `text` даёт непустой `ocr_markdown`; `stamp` даёт `ocr_json`, разбираемый в `StampBlockResult`;
6. повтор шага 1 тем же телом → `deduplicated: true`, те же `remote_*`, число строк не изменилось;
7. `INSERT` под `portal_reader` → `permission denied`.

Со стороны RD WEB отдельно нужен сквозной тест через **реальный** worker (не через мок подготовки):
`POST` → задача заклеймлена → модель вызвана → строка в `block_results` → строка во вью. И проход
гард-теста каскада удаления проекта (`tests/api/test_project_purge_tables.py`) на изменённой схеме.
