# Приём готовых кропов в RD WEB

> **ОТМЕНЕНО (2026-09-04).** Схема не реализована и реализована не будет: RD WEB
> перешёл на контракт снимка исполнительной документации
> (`rdweb.executive_document_snapshot.v1`, см. ADR-0027 и
> `temp/EXTERNAL_PORTAL_INTEGRATION.md`), где портал присылает исходный PDF и
> перечень обведённых областей, а вырезы строит сама RD WEB. Обратной ручки не
> существует. Документ сохранён как история переговоров: по нему видно, какие
> требования были выставлены и какие из них новый контракт закрыл.

Портал ИД присылает в RD WEB готовую картинку — страницу целиком либо вырезанный из чертежа
фрагмент: штамп или верхнюю надпись листа.
RD WEB её распознаёт и складывает результат в свою БД. Портал забирает текст прямым `SELECT` из вью
под read-only ролью.

PDF в RD WEB не передаётся, документа у такой картинки нет. Геометрия, разворот и DPI уже применены
к пикселям: резать и доворачивать не нужно.

**Один запрос — одна картинка.**

---

## 1. Запрос

```
POST /api/v1/external-crops
Content-Type: multipart/form-data
Authorization: Bearer <токен служебного принципала>
```

| Часть         | Тип               | Значение                                                                                                                     |
| ------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `file`        | `image/jpeg`      | Байты картинки                                                                                                               |
| `external_id` | string ≤ 128      | Идентификатор картинки. Присваивает портал, глобально уникален                                                               |
| `crop_sha256` | string, 64 hex    | sha256 байтов `file`, нижний регистр                                                                                         |
| `block_type`  | `text` \| `stamp` | Что на картинке. От этого зависит формат результата: у `text` — markdown, у `stamp` — JSON по вашей схеме `StampBlockResult` |

Провайдер, модель и промпт-профиль — настройка RD WEB под проект портала.

Размеры: обычно 1650 × 2338 — это лист A4; потолок — 3000 px по длинной стороне (≈6.4 Мпикс).
Картинка весит 0.1–1.1 МБ, обычно около 0.5; комплект из 220 листов — около 110 МБ.

Проверки на границе делаются до декодирования: MIME, размер байтов, габариты из заголовка.
Существующая у вас проверка (`central/guards.py`, `png_dimensions`) читает только PNG — под JPEG
понадобится свой разбор заголовка.

---

## 2. Ответ

**200** — картинка принята, задача создана, строка во вью существует:

```json
{ "external_id": "…", "duplicate": false }
```

`duplicate: true` — этот `external_id` с этим же `crop_sha256` уже принимался: новой задачи нет,
строка та же.

| Код     | Когда                                                      |
| ------- | ---------------------------------------------------------- |
| 200     | Принято                                                    |
| 401/403 | Удостоверение неверно, отозвано или не даёт прав на проект |
| 409     | Тот же `external_id` с ДРУГИМ `crop_sha256`                |
| 413     | Картинка больше потолка                                    |
| 415     | Тип файла не `image/jpeg`                                  |
| 422     | Поля отсутствуют или не проходят проверку                  |
| 429/5xx | Перегрузка, недоступность                                  |

Коды обязаны различаться по смыслу: 401/403 — только про удостоверение, 413/415/422 — только про
эту картинку, 429/5xx — только про временную недоступность.

## 3. Требования к приёму и хранению

| №   | Требование                                                                                                                            | Приоритет |
| --- | ------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| 1   | **200 отдаётся после фиксации транзакции.** Сразу после ответа строка видна во вью со `status='queued'`, без задержки и без повторов  | **P0**    |
| 2   | **`UNIQUE (external_id)` ограничением БД**, не проверкой в коде                                                                       | **P0**    |
| 3   | **Повтор:** тот же `external_id` + тот же `crop_sha256` → 200, `duplicate: true`, новой задачи не создаётся                           | **P0**    |
| 4   | **Конфликт:** тот же `external_id` + другой `crop_sha256` → 409                                                                       | **P0**    |
| 5   | **Дедупликация по содержимому картинки запрещена**: два разных `external_id` с одинаковыми байтами распознаются оба, строк во вью две | **P0**    |
| 6   | **`crop_sha256` сохраняется как есть** и отдаётся во вью без пересчёта                                                                | **P0**    |
| 7   | **Терминальная строка неизменна**: получив окончательный статус, не меняет ни статус, ни текст                                        | **P0**    |
| 8   | **Строка живёт ≥ 30 суток** после окончательного статуса                                                                              | P1        |

**Про пункт 6.** Внутренний хэш растра (`contracts/crop_preprocess/v1/pixels.py:150-170`)
считается по другой схеме и с плоским sha256 не совпадает: во вью нужно присланное значение, а не он.

## 4. Вью для чтения

Единственная поверхность чтения. Таблицы RD WEB портал не читает.

```sql
CREATE VIEW portal_block_results_v1 AS SELECT
  external_id, crop_sha256, status,
  ocr_markdown, ocr_text, ocr_json,
  error_code, error_message, updated_at
FROM …;

CREATE UNIQUE INDEX … ON … (external_id);
```

| Колонка         | Тип         | Значение                                                                                       |
| --------------- | ----------- | ---------------------------------------------------------------------------------------------- |
| `external_id`   | text        | То, что прислал портал. **Одна строка на `external_id`**                                       |
| `crop_sha256`   | text        | Эхо присланного значения                                                                       |
| `status`        | text        | `queued` \| `running` \| `success` \| `suspicious` \| `error` \| `non_retriable` \| `canceled` |
| `ocr_markdown`  | text        | Текст; портал читает его первым                                                                |
| `ocr_text`      | text        | Запасной источник текста                                                                       |
| `ocr_json`      | jsonb       | Для `stamp` — `StampBlockResult`                                                               |
| `error_code`    | text        | Код отказа                                                                                     |
| `error_message` | text        | Текст отказа                                                                                   |
| `updated_at`    | timestamptz | Последнее изменение строки                                                                     |

Портал опрашивает вью запросом `WHERE external_id = ANY(…)`.

**Нужна таксономия статусов** (P1): для каждого значения `status` — окончателен ли он и есть ли смысл
отправлять картинку заново под новым `external_id`. Для задач такой словарь есть
(`domain/task_terminal.py:44-51`), для результата блока — нет.

---

## 5. Роль для чтения

`portal_reader`:

- `GRANT SELECT` **строго на вью** `portal_block_results_v1`; прав на таблицы нет;
- `CONNECTION LIMIT` (порталу достаточно 2);
- `statement_timeout` и `idle_in_transaction_session_timeout` на роли;
- TLS обязателен, CA-сертификат передаётся отдельно от пароля (портал подключается с
  `sslmode=verify-full`);
- сетевой allowlist по адресам портала, процедура ротации пароля.

**Удостоверение для приёма** (P1): токен службы с областью «только приём внешних кропов в указанные
проекты», хранимый хэшем, отличимый от JWT по префиксу — по образцу агентского механизма
(`domain/models_agents.py:43`, `api/services/agent_auth.py:14-16`). До него — отдельный служебный
аккаунт.

## 6. Что придётся тронуть в конвейере

Сегодня подготовка вызова безусловно грузит документ и режет кроп сама, а `document_id` объявлен
`NOT NULL` у блоков, задач и job-ов (`030_blocks_results.sql:9`, `040_jobs_tasks.sql:9,41`).
У присланной картинки документа нет — нужна отдельная ветка исполнения:

| Точка                                              | Что меняется                                                                                                                                          |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pipeline/processor_prepare.py:66-68`              | `get_document` не должен быть обязательным: контейнер-документ либо снятие `NOT NULL`                                                                 |
| `pipeline/processor_prepare.py:155` (`build_crop`) | Пропускается: байты берутся из загрузки по сохранённому ключу объекта                                                                                 |
| `pipeline/lineage_record.py:93,98`                 | Ожидаемый хэш строится из загруженных байтов; сверка `queue.crop_lineage` не отвергает сдачу за «чужой» растр (`api/services/agent_result.py:92-101`) |
| `pipeline/processor_preflight.py:129,401`          | Бюджет контекста — по размерам присланной картинки; ужатие при переполнении — перекодированием, а не перерастеризацией `crop.pdf` (его нет)           |
| `pipeline/refinement/*`, `verification/*`          | Ветка без документа не должна падать: у картинки нет ни `crop.pdf`, ни текстового слоя. Зонд уже умеет `crop_pdf_missing` (`pdf_text_layer.py:167`)   |
| `api/services/project_purge_tables.py:18,55`       | Новую таблицу внести в `PURGED_TABLES` или `KEPT_TABLES` с причиной, иначе гард-тест каскада упадёт                                                   |

Признак внешнего блока — новая колонка `blocks`. Имя на ваше усмотрение, но **не** `crop_source`: оно
занято другой осью — чем кормится модель на агентском узле, значения `''`, `local_shadow`, `local`
(`api/routes/_agent_schemas.py:199-201`).

**Не меняется:** схема `StampBlockResult` (`domain/results.py:148-178`) — поле-в-поле как есть;
промпты и модели; существующий путь «документ → детекция → job»; векторный `crop.pdf` для внутренних
блоков; агентский путь.

## 7. Вопросы

1. **Потолок размера картинки.** Какой размер тела пропускает ваш контур и какой потолок вы
   поставите на ручке? Конфигурации обратного прокси в репозитории нет. Существующая граница растра
   блока — 12 МиБ и 40 Мпикс после декодирования (`central/guards.py:41,45`); присылаемая картинка
   укладывается в обе с запасом: до 1.1 МБ и до 6.4 Мпикс.
2. **`crop_model_dpi`** (`core/settings_models_queue_provider.py:18`, значение 300) описывает
   растеризацию вашего кропа. Подтвердите, что к присланной картинке она не применяется.
3. **Меняют ли `refine` / `verify` уже терминальную строку?** У результата есть `result_phase`,
   `source_result_id`, `is_final` (`030_blocks_results.sql:41-43`) — портал должен знать, может ли
   текст смениться после того, как он его прочитал.
4. **Автоматическая уборка результатов по сроку** — есть ли она на уровне эксплуатации и
   распространяется ли на присланные картинки (требование 8)?

## 8. Проверка

Приёмочная проверка:

1. `POST` картинки типа `text` → 200;
2. немедленный `SELECT` из вью под `portal_reader`, без задержки → строка есть, `status='queued'`;
3. опрос до окончательного статуса → `success`;
4. `crop_sha256` во вью посимвольно равен отправленному;
5. `ocr_markdown` непустой; для картинки типа `stamp` — `ocr_json` разбирается в `StampBlockResult`;
6. повтор шага 1 тем же файлом → 200, `duplicate: true`, число строк не изменилось;
7. `POST` с тем же `external_id` и другим файлом → 409, строка не изменилась;
8. `INSERT` под `portal_reader` → `permission denied`.

Со стороны RD WEB отдельно нужен сквозной тест через **реальный** worker, а не через мок подготовки:
`POST` → задача заклеймлена → модель вызвана → строка в `block_results` → строка во вью. И проход
гард-теста каскада удаления проекта (`tests/api/test_project_purge_tables.py`) на изменённой схеме.
