# ADR-0003. Инструмент работы с PDF: qpdf с деградацией на pdf-lib

Дата: 2026-08-17. Статус: принято.

## Контекст

Конвейеру нужны две операции над PDF: собрать рабочий документ из нескольких
исходных файлов (§3.3) и нарезать логические документы по диапазонам страниц
(§7). Реальные комплекты — до 86 МБ на 83 страницы, и обе операции выполняются
в фоновых задачах, которые идут параллельно.

План выбрал `qpdf`, потому что `pdf-lib` загружает документ в память целиком:
86 МБ PDF превращаются в 300+ МБ heap, а при нескольких одновременных задачах
это OOM на одной VPS. `qpdf` работает потоково, не перекодирует сканы и
сохраняет качество.

Проверено на машине разработки: **`qpdf` отсутствует**, как и `pdftk`
и `ghostscript`. `pdf-lib` доступен.

## Решение

Интерфейс `PdfToolkit` с двумя реализациями и явным выбором:

- **`QpdfToolkit`** — боевая. Требует бинарник в образе воркера. Единственная,
  которой разрешено обрабатывать файлы крупнее порога.
- **`PdfLibToolkit`** — деградация. Используется в тестах, в разработке и для
  файлов ниже порога (по плану — 20 МБ).

Выбор реализации делает startup check, а не место вызова:

- `NODE_ENV=production` и `qpdf` не найден → **процесс не поднимается**.
  Молчаливая деградация в проде означала бы OOM на первом крупном комплекте,
  причём в фоновой задаче, то есть без внятной ошибки пользователю.
- Вне production отсутствие `qpdf` даёт предупреждение при старте и
  ограничение по размеру файла. Задача с файлом крупнее порога завершается
  понятным отказом «нужен qpdf», а не падением по памяти.

## Последствия

Синтетические фикстуры малы, поэтому тесты сборки и нарезки полноценно
работают на `pdf-lib` и проверяют логику: карту страниц, границы диапазонов,
пометку производной копии.

**Зафиксированный долг.** Поведение на реальном 86 МБ комплекте — расход
памяти, время, отсутствие перекодирования сканов — на этой машине непроверяемо.
Гейт «нагрузка: одновременная обработка нескольких файлов до 200 МБ без
превышения memory budget» (§16) остаётся открытым до S12, где появится целевая
VPS с установленным `qpdf`. Это тот же класс долга, что тесты конкурентного
захвата задач на одноконнектном pglite (ADR-0002): проверяемое проверяется
сейчас, непроверяемое отслеживается явно, а не считается сделанным.
