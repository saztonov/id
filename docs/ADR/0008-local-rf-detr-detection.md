# ADR-0008. Локальная детекция блоков: RF-DETR (ONNX) на CPU воркера

Дата: 2026-08-20. Статус: принято.

## Контекст

Автодетекция блоков (text/image/stamp) шла через legacy-API RD WEB
(`POST /documents/{id}/detect-blocks`, ADR-0004): портал загружал рабочий PDF
к ним и забирал блоки. Заказчик решил (2026-08-20) выполнять детекцию локально:
модель — **RF-DETR** (Roboflow; в обиходе её называли «YOLO», что неверно),
экспортированная в ONNX; RD WEB сам в проде исполняет её на CPU через
onnxruntime (`detection.execution_provider: cpu` в их настройках), GPU нужна
только обучению. Вместе с переводом OCR на OpenRouter (ADR-0007) это убирает
RD WEB из рантайма полностью.

Ограничение: эндпоинта скачивания модели у RD WEB нет — файл `model.onnx` и
`onnx_export_manifest.json` передаются организационно их командой.

## Решение

### Модель и манифест — контракт

Пара «веса + манифест» кладётся администратором в хранилище портала под
`models/detection/{version}/` (`detectionModelKey`/`detectionManifestKey`);
версия — настройка `detection.model_version`. Манифест — единственный источник
параметров инференса: разрешение, mean/std препроцессинга, box_format,
активация, top-K, per-class пороги, тайлинг, `class_mapping
{text:0, image:1, stamp:2}` (валидируется жёстко). Ничего из этого не
хардкодится: смена модели — это новые файлы и новая версия в настройке, не
релиз. Целостность — sha256 при загрузке в воркер, скачивание во временный
файл с атомарным rename; кэш `InferenceSession` в памяти процесса; идущая
пачка детекции не смешивает версии (версия читается на постановке).

### Разделение чистой логики и нативной обвязки

- `packages/detection` — чистый порт числовой части референса
  (`temp/RDNEW/services/web_ocr/detection/`): разбор манифеста, тайлинг и
  обратный remap, декодирование выходов (sigmoid/softmax, top-K по
  query×class, no-object столбец), class-aware NMS, объединение разорванных
  боксов ТОЛЬКО класса text, пороги, потолки. Ноль нативных зависимостей,
  полная тестируемость; WBF не портирован (по умолчанию не используется).
  Паритет с Python держат фикстуры (`tools/fixtures/detection/`).
- `apps/worker/src/detection/` — нативная обвязка: препроцессинг sharp
  (квадратный resize без letterbox, как при обучении), `onnxruntime-node`
  (CPU EP, intra/inter-op потоки ограничены), model-store, оркестрация
  страницы. Сессия — за портом, мокается в интеграционных тестах.

### Растеризация

Серверных изображений страниц у портала не было (экран рендерит pdf.js в
браузере; серверные PNG приходили только из превью RD WEB). Вводится порт
`PageRasterizer` (`apps/api/src/pdf/raster.ts`) по прецеденту ADR-0003:
боевая реализация — внешний `pdftoppm` (poppler-utils, ~300 DPI — разрешение
обучения детектора), обнаруживается при старте; отсутствие — warning и
честный отказ зависимых задач, процесс поднимается (обе новые ветки —
опциональные настройки). WASM-фолбэк `@hyzyla/pdfium` для машин разработки —
отдельный шаг; `selectRasterizer` устроен списком кандидатов. PNG эфемерны
(scratch задачи), в хранилище не пишутся. Вид и версия растеризатора и DPI
фиксируются в снимке прогона.

### Задача и провенанс

`layout.detect_local` (очередь cpu): страницы пачки → рендер → инференс →
`importBlocks` с `detector_provenance='rf_detr'` и НОВЫМИ полями
`detection_score`, `detection_model_version` (миграция 0019) — локальный
инференс, в отличие от легаси-API, уверенность знает; блоки от RD WEB и
ручные честно хранят NULL. Страница с нулём детекций фиксируется терминально
— повтор задачи не детектирует её заново. Ветка выбирается настройкой
`detection.provider` (`rdweb | local`) на постановке; legacy-цепочка `rd.*`
не тронута и остаётся откатом.

### Дообучение — вне портала

Тренер RF-DETR остаётся у RD WEB (GPU); в датасет у них берётся только ручная
разметка. Ручные блоки портала (`layout_blocks.source='user'`) — будущий
датасет дообучения на исполнительной документации; экспорт в COCO — отдельный
этап, здесь не проектируется.

## Последствия

- Предусловия эксплуатации: файл модели от команды RD WEB; `poppler-utils`,
  `sharp`, `onnxruntime-node` в образе воркера; замер RSS и латентности
  инференса на целевой VPS до поднятия конкуренции (старт — 1).
- Препроцессинг sharp не бит-в-бит с PIL BILINEAR; допуск фиксируется
  IoU-тестами на золотых страницах, пороги манифеста не подгоняются.
- Комбинация local-детекции с RD WEB OCR не поддержана (409, ADR-0007):
  у ревизии нет RD-документа; откат целиком — обе настройки в `rdweb`
  и переразметка.
- `PREVIEW_MODE=cached` при локальной детекции недоступен (превью брались у
  RD WEB) — принудительно pdfjs с warning; локальная генерация кэша превью
  через тот же растеризатор — отдельный небольшой этап.
