# ADR-0002. Тестовая БД для гейтов

Дата: 2026-08-17. Статус: принято.

## Контекст

На каждом этапе гейт должен проверять миграции и SQL-логику на настоящей PostgreSQL. На машине разработки **Docker и psql отсутствуют** (проверено), CI-раннера нет. Статический разбор SQL настоящую БД не заменяет.

## Рассмотренные варианты

**`embedded-postgres`** — скачивает настоящие бинарники PostgreSQL. Отвергнут: у пакета **нет ни одного стабильного релиза**, `latest` указывает на `18.4.0-beta.17`.

**`testcontainers`** — требует Docker, которого нет.

**`@electric-sql/pglite`** — настоящий PostgreSQL, собранный в WASM, работает в процессе Node без внешних зависимостей. Drizzle поддерживает его официально (`peerDependencies: "@electric-sql/pglite": ">=0.2.0"`).

## Решение

Основной инструмент — **pglite 0.5.5**. Проба на S0 подтвердила: PostgreSQL 18.3, расширения `pgcrypto`, `citext`, `pg_trgm` доступны, `gen_random_uuid()` и `similarity()` работают.

Существенная деталь реализации: в pglite contrib-расширения не встроены в ядро. Их бандлы подключаются опцией `extensions` при создании инстанса, и только после этого `CREATE EXTENSION` находит control-файл. Без этого запрос падает в `parse_extension_control_file`.

## Признанное ограничение

pglite **одноконнектный**. Истинная конкурентность — захват задачи двумя воркерами через `FOR UPDATE SKIP LOCKED` — на нём непроверяема.

Такие тесты помечаются `skipIf(!hasRealPostgres())` и загораются автоматически, как только задана `TEST_DATABASE_URL`. Это **зафиксированный долг**, а не закрытый вопрос: гейт «миграции и конкурентность на настоящей PostgreSQL» входит в список non-degradable и обязан быть закрыт до завершения S12.

## Последствия

Локальные гейты проверяют настоящую семантику PostgreSQL, а не парсинг SQL. Цена — один класс тестов откладывается до появления реальной БД, и это явно отслеживается.
